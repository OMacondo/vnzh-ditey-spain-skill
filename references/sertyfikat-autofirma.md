# Цифровий сертифікат і AutoFirma

Для Apodera і Mercurio потрібен **іспанський** цифровий сертифікат (FNMT або ACCV) чи Cl@ve. Український КЕП (`.pfx` з Дії, банку тощо) **не підходить**.

**Пароль сертифіката вводить лише користувач.** Ти його не шукаєш, не читаєш і не вводиш.

Приватний ключ сертифіката юридично рівноцінний власноручному підпису. Тому з усіх способів спершу пропонуй найбезпечніший, а ті, що послаблюють захист ключа, лише як запасний варіант і завжди з поясненням ризику.

## Що перевірено
- ✅ Сертифікати ACCV в обох батьків, Mac, Chrome, AutoFirma. Підписи в Apodera і в Mercurio спрацювали.
- ✅ Вхід у Mercurio сертифікатом (через шлюз Cl@ve).
- ⚠ Вхід через Cl@ve PIN/Permanente і підпис без сертифіката (хмарний Cl@ve Firma) не перевіряли. Тому краще, щоб у того, хто подає, був сертифікат.
- ⚠ Як отримати сертифікат, скіл не перевіряв: у нас вони вже були.
- ⚠ Windows не перевіряли.

## Якщо сертифіката немає (⚠ не перевірено)
- **FNMT:** запит на sede.fnmt.gob.es, далі ідентифікація в офісі за записом (або відеоідентифікація, якщо вона доступна). Потім сертифікат завантажують **у тому самому браузері на тому самому комп'ютері**.
- **ACCV** (видає Валенсійська Генералітат, діє по всій Іспанії): у пунктах реєстрації або через сервіси з відеоідентифікацією.
- **Cl@ve:** реєстрація через застосунок Cl@ve або в офісі. Для входу її достатньо, для підпису див. вище.
- Сертифікат **особистий**: кожен із батьків підписує своїм. Не пересилай сертифікат із паролем агенції: для цього існує довіреність Apodera.
- Новий сертифікат може запрацювати на держсайтах не одразу. У нас перший вхід зі щойно виданим сертифікатом видав помилку, а згодом усе запрацювало.
- Перевірити сертифікат можна на valide.redsara.es. Там перевіряють лише публічну частину: файл `.cer`/`.crt` або сертифікат, уже встановлений у браузері. **Ніколи не завантажуй на сайти `.p12`/`.pfx`**: у такому файлі лежить приватний ключ.

## Стандартний шлях на Mac
1. **AutoFirma:** firmaelectronica.gob.es → *Descargas* → версія для свого Mac (Apple Silicon або Intel) → встановити → **повністю закрити браузер** (Cmd+Q) і відкрити знову.
2. **Імпорт сертифіката** у зв'язку **login** (не iCloud): через Keychain Access (*File → Import Items…*) або в Терміналі. Пароль сертифіката macOS запитає у своєму вікні.
   ```bash
   security import ~/Downloads/cert.p12 -k ~/Library/Keychains/login.keychain-db
   ```
   Не додавай прапорець `-A` без потреби: він дає **будь-якій** програмі на цьому Mac доступ до приватного ключа без запиту.
3. **Перевірка:** Keychain Access → login → *My Certificates* → сертифікат з ім'ям і NIE, а під ним ключ.
4. **Перший вхід і перший підпис:**
   - браузер питає, чи відкрити AutoFirma → дозволь;
   - вибери сертифікат (вікно AutoFirma може з'явитися **позаду** браузера, шукай іконку в Dock, інакше буде таймаут);
   - macOS питає доступ до ключа → пароль від Mac → **Always Allow**. Так доступ отримує лише ця програма: спершу Chrome (вхід сертифікатом), потім AutoFirma (підпис).
5. Позначка «not trusted» біля сертифіката ACCV роботі AutoFirma в нас не заважала.

✅ AutoFirma, вхід і підписи сертифікатом у нас спрацювали. ⚠ Але сам звичайний імпорт без `-A` до кінця не перевірений: перший імпорт закінчився помилкою «La entrada no tiene clave privada», а спрацював імпорт перепакованого файлу з `-A` (див. нижче). Безпечніший шлях подано першим, бо в інших користувачів він може спрацювати.

## Якщо щось пішло не так (траплялося в нас, у вас може й не бути)
Ці проблеми виникли на одному конкретному Mac (macOS 26, сертифікати ACCV). Найімовірніше, вони локальні. Не виконуй ці кроки наперед, а лише тоді, коли з'явилася саме така помилка.

| Симптом | Що робити |
|---|---|
| Помилка `-26276` під час імпорту | Часто означає, що вибрано зв'язку **iCloud**. Імпортуй у **login** |
| «MAC verification failed» / «passphrase not correct», хоча пароль правильний | Спершу перевір пароль: `openssl pkcs12 -in file.p12 -noout -legacy` (якщо помилки немає, пароль правильний). Наш файл від ACCV містив, крім особистого сертифіката, ще 3 сертифікати центру ACCV, і macOS відкидав увесь файл з оманливим «неправильний пароль». Допомогло перепакувати лише особистий сертифікат і ключ (див. нижче) |
| AutoFirma бачить сертифікат, але в журналі *«La entrada no tiene clave privada»* | AutoFirma не має доступу до ключа. 1) Переконайся, що є резервний `.p12` і пароль до нього. 2) Видали сертифікат у *My Certificates* і «осиротілі» ключі у вкладці *Keys*. 3) Імпортуй заново й при першому підписі натисни **Always Allow**. 4) Якщо не допомогло, запасний варіант (так спрацювало в нас): імпорт з `-A`. ⚠ `-A` дає доступ до ключа будь-якій програмі на цьому Mac без запиту, тому роби так лише на власному комп'ютері, якому довіряєш |
| AutoFirma не відкривається | Перевір, що вона встановлена (у нас спершу її просто не було). Після встановлення перезапусти браузер |
| AutoFirma зависає або таймаут | Закрий процес AutoFirma, перезапусти браузер і швидко вибери сертифікат у вікні |
| Сертифікат «not trusted» заважає підпису | Користувач сам ставить *Trust → Always Trust* на кореневому сертифікаті ACCV, але спершу звіряє його відбиток (SHA-256) з опублікованим на офіційному сайті ACCV. У нас цього не знадобилося |
| Помилка `23005832` під час входу через Cl@ve | Браузер міг підставити не той сертифікат: закрий його повністю (Cmd+Q) і вибери правильний. Свіжий сертифікат може запрацювати лише через кілька годин |
| Загубився пароль | Відновити його неможливо. Шукай у «Паролях», нотатках, листах самому собі в день видачі сертифіката. Якщо не знайдеш, доведеться отримати новий сертифікат |

### Перепакування `.p12` лише з особистим сертифікатом (Mac)
Потрібен OpenSSL 3 або новіший, наприклад з Homebrew (`brew install openssl`). Вбудований у macOS `/usr/bin/openssl` (LibreSSL) опції `-legacy` не знає. Усі паролі користувач вводить у Терміналі сам. Команди працюють у zsh (стандартна оболонка macOS) і в bash.
```bash
printf 'Пароль від original.p12: '; read -s P12IN; echo; export P12IN
printf 'Новий пароль для me-only.p12: '; read -s P12OUT; echo; export P12OUT
openssl pkcs12 -export -legacy -certpbe PBE-SHA1-3DES -keypbe PBE-SHA1-3DES -macalg sha1 -inkey <(openssl pkcs12 -in original.p12 -legacy -nodes -nocerts -passin env:P12IN) -in <(openssl pkcs12 -in original.p12 -legacy -clcerts -nokeys -passin env:P12IN) -passout env:P12OUT -out me-only.p12 -name "NAME SURNAME"
openssl pkcs12 -in me-only.p12 -legacy -nodes -passin env:P12OUT | grep -c BEGIN   # має бути 2: сертифікат і ключ
unset P12IN P12OUT
security import me-only.p12 -k ~/Library/Keychains/login.keychain-db
```
- Незашифрований ключ **не записується на диск**: між командами він іде каналами `<(...)`.
- Паролі передаються через змінні середовища, а не в тексті команди, і після роботи стираються (`unset`).
- Результат має формат SHA1 + 3DES, який macOS приймає.
- Якщо після імпорту AutoFirma пише «no tiene clave privada», див. таблицю вище: там описано запасний варіант з `-A`.

Оригінальний `.p12` не видаляй: це резервна копія. Для іншого Mac бери `me-only.p12`.

## Windows (⚠ не перевірено)
Подвійний клік по `.p12` → *Usuario actual / Current User* → пароль → автоматичний вибір сховища. Перевірити в Chrome/Edge: *Configuración → Privacidad y seguridad → Seguridad → Administrar certificados*. Firefox може мати власне сховище, тоді туди сертифікат імпортують окремо.

## Чим ти можеш допомогти (Mac)
- Перевірити, чи встановлена AutoFirma: `ls /Applications | grep -i autofirma`.
- Перевірити, чи є в Keychain сертифікат із ключем: `security find-identity` **без** `-v`. З `-v` недовірені сертифікати ACCV не показуються взагалі. Шукай рядок з ім'ям і NIE в розділі *Matching identities*.
- Подивитися журнал AutoFirma: `~/.afirma/AUTOFIRMA.afirma.log.xml`.
